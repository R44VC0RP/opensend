# AWS permission review: Hosted v8 / customer v5 — not released

Baseline: `7527783`, published BYO v4 and operator-reported default Hosted v7. **Do not install on the current Worker.** This review used source and public AWS references; the `anomaly` SSO session had expired. Neither the default version, the 12 adopted Virginia ARNs nor an empty Ireland inventory was independently verified. The checker verifies the actual default, document and attachments, not just a version number. The failed v6 must never be the fallback. For the earlier CloudTrail analysis and simulations (not evidence for these drafts), see `git show 7527783:infra/aws-shared/iam-review.md`.

## Scope and contracts

* **Hosted:** commercial account `438095551154` only. Virginia sends with `opensendmx-trusted-{transactional,marketing,feedback}` and `opensendmx-trusted-ws_<32>`; all receiving stays in Ohio. Ohio keeps its exact legacy `opensend-mx-{transactional,marketing,feedback,inbound}` resources, existing mailbox bucket, `opensend-ws_<32>` tenant bindings, identities and claim tokens; **no rename, bulk retag or reassociation**. Fresh tenants are `opensendmx-probation-ws_<32>` there. Both new tenant types, new identities, trusted sets/topic and disposable sets carry `opensend:owner=mx`, `opensend:installation-id=opensend-mx:pool`, and the specific purpose. The Ohio legacy infrastructure statements remain pinned exceptions, not a new-install naming scheme. Identity names are DNS names, not prefixed. All Allow resources with a regional ARN pin the account and region; the sole AWS-owned resource is each pool's exact `reputation-policy/strict`. Both endpoint and applicable resource-ARN Denies remain. Receipt operations / S3 are **explicitly denied outside Ohio**. No Virginia access to self-hosted `opensend-042df6f752eaa1f62cb8-*` sets/topic/bucket or its active set.
* **Adoption:** the primary source document denies *all* edits to Virginia identities until `runtime-policies.mjs` renders the operator's private, attested list of 12 exact ARNs. On each adopted ARN, only `GetEmailIdentity` and `SendEmail` escape the **explicit deny**, even if someone later changes its tags. The migration operator, **not** the runtime, associates approved adopted identities with their tenant. Do not infer the manifest from a general list of verified domains. No secret or real customer identity inventory belongs in Git.
* **BYO:** the sole role is global and named by the `OpenSendMX-<20>` stack; conditional receiving adds only a customer-managed IAM policy, not regional infrastructure. The `NotPlatform` Rule compares the actual account with a non-overridable allowed platform account before resource creation. Trust pins the IAM user, external UUID and session name. `P=opensendmx-<first 20 hex SHA256(connectionId)>`, exact `P-transactional`, `P-marketing`, `P-feedback`, and optional `P-inbound`. Bind those parameters to the verified DB connection/workspace; a CloudFormation pattern does not compute a hash. Reads cover the [32 commercial SES sending endpoints](https://docs.aws.amazon.com/general/latest/gr/ses.html); no CloudWatch or mail-content read for scan. The two optional switches are independent, default **false**; their region lists are customer-controlled. The customer can deploy the role from a non-SES commercial stack region. No SES tenant, global sending endpoint, SMTP, IAM, Support, account suppression management or DNS grants in the role.
* **Unavoidable boundaries:** SES can't restrict `CreateReceiptRule` / `DeleteReceiptRule` to a name or match set, event destinations are authorized on the parent set, and SNS can't restrict the body of `SetTopicAttributes` or enforce raw=false on Subscribe. Exact names alone are not ownership. Verify ARN, account, tags, journal and complete destination/subscriber/rule fingerprints **before** any mutation; block drift, never overwrite it. Only signed SNS confirmations/notifications from the registered regional topic are accepted. Set deletion also deletes its destinations; topic deletion also removes subscriptions. `PutBucketPolicy`, lifecycle and `PutBucketTagging` can affect all data in the exact bucket. IAM does not prove a bucket is newly created or that a rule belongs to MX. Require customer-approved rules/order and provenance before changing either. No bucket/object delete grant. `GetEmailIdentity` must see untagged candidate domains. The BYO base role can send from verified domains in the account; the import checkbox alone is **not** an IAM boundary. A send session must narrow to the selected domain identity and two exact config sets in the bound account/region. An operator wanting account-level isolation should use a dedicated account.

These artifacts constrain the **MX** principal, not other principals in the account. The self-hosted `api/iam-policy.json` example has `opensend-*` set/topic globs, broader identity administration and unscoped classic receipt actions. Before co-residence, independently inventory and narrow the **installed self-hosted** principal to its legacy region/resources; do not edit or apply that example as part of this rollout.

## Ireland retirement gate

`provider-connections.ts:36–54,254–280` defaults Hosted to Ohio; `api/wrangler.mx.jsonc` does not configure Ireland. This is evidence about deployment **defaults**, not proof of no stored work. Draft v8 removes all Hosted Ireland access (customer STS still usable). **Block release** until the operator checks deployed configuration/overrides, `provider_pool_regions`, shared `provider_connections`, pending/unknown sends and campaigns, late feedback/retries, mailbox bindings/history and CloudTrail for the Worker user in `eu-west-1`. No AWS inventory at authoring time. The checker independently reads Ireland's SES tenant/set/claimed identities, SNS topics, active/inactive-set rules and account bucket inventory and stops on plausible MX resources or denied reads. If any resource/traffic remains, drain or get an explicit separate retention decision; don't silently abandon it or grant Ireland again.

## Release later — run only with operator approval

1. **Prepare and verify.** Serialize the release. Finish the Ireland and 12-identity reviews, inspect actual `aws --profile anomaly iam get-policy --policy-arn arn:aws:iam::438095551154:policy/opensend-mx` and `list-policy-versions`; require the known-good v7. 2. **Stage, don't activate.** From repository root, run the following with `MANIFEST` already set. The companions must be unused; if staging resumes after failure, compare their documents, don't overwrite them. The renderer validates all 12 ARNs and all three post-substitution policy sizes before writing anything. Review Access Analyzer results and run isolated scoped positive/negative simulations before activation. An IAM simulator result does not prove SES/SNS supplies resource tags on the dependent API authorization.

   ```sh
   set -eu
   export AWS_PROFILE=anomaly AWS_REGION=us-east-2
   umask 077
   D=$(mktemp -d); I=infra/aws-shared; A=arn:aws:iam::438095551154:policy/opensend-mx
   for n in opensend-mx opensend-mx-ohio-v8 opensend-mx-trusted-v8; do
     node "$I/runtime-policies.mjs" "$MANIFEST" "$n" > "$D/$n.json"
     aws accessanalyzer validate-policy --policy-type IDENTITY_POLICY --policy-document "file://$D/$n.json" --query findings
   done
   # STOP to review findings and effective policies. Only after approval:
   for n in opensend-mx-ohio-v8 opensend-mx-trusted-v8; do
     aws iam create-policy --policy-name "$n" --policy-document "file://$D/$n.json" --tags Key=opensend:owner,Value=mx
   done
   V=$(aws iam create-policy-version --policy-arn "$A" --policy-document "file://$D/opensend-mx.json" --query PolicyVersion.VersionId --output text)
   ```

3. **Activate under the checker.** Run `deadbolt run --env OPENSEND_E2E_API_KEY="$E2E_KEY_REF" -- node "$I/check-release.mjs" "$V" v7 "$MANIFEST"`, where `E2E_KEY_REF` is the approved Deadbolt field reference. Every dangerous denial is tested with `simulate-principal-policy` against the actual user, never by attempting a real receipt write or deleting a foreign resource. Positives use the actual worker user for tagged create/delete in each region; API simulator sends require exclusive tenant membership, the expected set→topic, correct region/from/to/provider ID, and a nonsynthetic delivery event through signature-verified ingress. Then it verifies a new Hosted identity's tags and removal and runs the existing full E2E. **Only after success** enable scoped enrollment. A rollout with no pre-staged trusted fixture must stop at step 1; don't point it at Anomaly's mail instead.
4. **Rollback.** On failed canary/handled signal after arming, the script restores v7 first, detaches only the companions it attempted to attach, verifies the original policy set and cleans the exact run-owned objects. For a killed process, lost access or concurrent release: disable enrollment/writes, restore the v7-compatible Worker behavior, inspect the actual default and attachments; **only if still this release**, run `aws iam set-default-policy-version --policy-arn "$A" --version-id v7`, then `aws iam detach-user-policy --user-name opensend-mx --policy-arn "$A-ohio-v8"` and likewise `"$A-trusted-v8"` for attached companions. This rollback restores authorization; it does not retract sent mail or revert data/DNS.
