# OpenSend MX: tenant-isolation map

**Keep `default` as the existing workspace ID. Do not enable a second workspace merely by changing `config.workspaceId`.** That would leave three release blockers: dashboard administrators can list and revoke other users’ MCP grants; unrestricted senders can use another tenant’s SES-verified domain; and feedback batches assign every item to one workspace (`mcp-auth.ts:353–372`; `sending.ts:241–248,1116–1137`; `operations.ts:200–212,563–597`).

Paths below are relative to `api/src/` unless specified. The table groups the **76 direct production reads** of `config.workspaceId` with their dependent queries. The exact line inventory is reproducible with `git grep -nF 'config.workspaceId' -- api/src`.

### Data model and query boundaries

- Add `workspaces(id,slug,status)`, `memberships(workspace_id,user_id,role,status)` with composite PK, `domain_claims`, provider connections, and trusted regional topic bindings. Add workspace FKs to tenant-owned rows. Store the chosen workspace on the OAuth grant or a companion grant table; access/refresh tokens must resolve that immutable choice (`db/google-auth.ts:4–34`; `db/mcp-auth.ts:39–59`; `db/ses-regions.ts:4–18`).
- **Tables without `workspace_id`:** `sending_review_recipients`, `mailbox_write_lanes`; `auth_{user,session,account,verification,jwks}`; `oauth_{client,resource,client_resource,refresh_token,access_token,consent,client_assertion}`; `opensend_migrations`. Keep identity, protocol registry and migration ledger global. Add scope to recipients and lanes; update bulk insertion and deletion trigger (`db/sending.ts:70–76`; `db/mailbox.ts:24`; `audience.ts:140–150`; `api/migrations/026_review_recipients_bulk_insert.sql:7–15`; `migrate.ts:24`).
- **Non-scoped uniqueness:** retain global opaque IDs, credential/capability hashes and provider-envelope dedupe `(topic_arn,message_id)` when each outbound envelope has one owner. Add same-owner composite references for review/ordinal, expansion campaign/review, mailbox-message/thread pairs, one public address per mailbox and webhook/event deliveries. Scope sequence identity if numbering per tenant (`db/core.ts:3–7`; `db/operations.ts:15–16`; `db/sending.ts:38,48–50,71–78`; `api/migrations/020_mailboxes.sql:154–187,228–246,274–288`; `036_mailbox_public_address.sql:5`).
- **Query audit:** audience CRUD/SQL, imports, consent, local templates/assets and send idempotency already scope root queries (`audience.ts:43–109,157–175,225–364`; `audience-query.ts:18–176`; `templates.ts:47–113`; `sending.ts:221–240,275–318`). ID-only follow-ups rely on globally unique, previously authorized parents—not necessarily current leaks. Harden campaign review/expansion reads and writes (`sending.ts:890,932–989,1021–1053,1255,1342–1401,1490–1565`), mailbox projections/mutations/downloads (`mailbox.ts:154–298,348–427,503–669,711–832,966–1029`; `inbound-threads.ts:45–111,136–175`; `mailbox-store.ts:114,161–187`; `mailbox-send.ts:31–43,90–145,252–275`; `mailbox-ingest.ts:137–148`).
- **Dashboard:** routes/deep links have no workspace; requests, query keys, prefetch and persisted region select only environment or origin (`app/src/App.tsx:64–77`; `app/src/data/live.ts:5–10,61–68,95–110`; `app/src/data/context.tsx:13–36,60–83,107–111`; `app/src/data/regions.ts:6`; `sending.ts:204–208`).

### Migration order and release gates

1. **Add, don’t rename.** Seed `default`, backfill currently approved users as its admins and bind existing grants/provider resources. Preserve IDs, object keys, webhook encryption bindings and cursors. Replace the migration guard that rejects any second namespace; do not edit checksummed migrations (`migrate.ts:16–43`; `sending.ts:572`; `operations.ts:92`).
2. Deploy membership-aware API and dashboard with tenant creation disabled. Backfill child ownership and validate composite constraints while the old workspace remains operational (`db/sending.ts:70–78`; `db/mailbox.ts:87–100`).
3. Upgrade workers and callback routing before admitting new tenants. Accept legacy queue/DO identities **only for `default`** during drain; preserve old topics for delayed feedback (`core.ts:59`; `dispatcher-do.ts:50–73`; `ses-region-state.ts:75–81`).
4. Gate launch on two-workspace tests: foreign MCP list/revoke and revoked queued authority; overlapping sender domains and SES templates; mixed feedback/replayed receipts; BCC/raw MIME, attachments and event cursors; identical contact/idempotency inputs, webhook retry and warm dashboard caches. Use the isolated acceptance database, not production (`api/AGENTS.md` policy in repo `AGENTS.md:34–36`; relevant query sites above).
