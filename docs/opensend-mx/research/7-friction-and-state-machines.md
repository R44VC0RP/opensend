# OpenSend MX audit: friction and implicit state machines

Read-only. Builds on `6-knob-audit.md`; items already there are referenced, not repeated.

## 1. Top 10 changes (friction/bug-risk removed × ease)

1. **`WEBHOOK_ALLOWED_HOSTS=""` still blocks every webhook on opensend.mx.** `api/wrangler.mx.jsonc:33` + `api/src/operations.ts:69`. Every `POST /v1/webhooks` and `/v1/inbound/webhooks` returns `WEBHOOK_HOST_NOT_ALLOWED`. Carbon flagged it; it's still shipped. Delete the allowlist branch; keep lines 66-68 (HTTPS, no creds/IP/internal TLDs). Workers' `fetch` cannot reach RFC1918/loopback at all, so DNS-rebinding into private space is not a real risk on this deployment. Also drop the `port !== 443` rule (same line) — it blocks nothing an attacker needs and breaks `:8443` endpoints.

2. **Collapse the domain claim into two explicit enums.** Today one domain's state lives in `domain_claims.verified`, `.ready`, `.readiness` (JSON with its own `sending`/`receiving`/`verificationStatus`/`dns[].status`), `.receiving_name`, `.receiving_eligible`, `.txt_misses`, `.mx_misses`, plus a mirrored `mailbox_domains.status`/`.mx`/`.enabled_at` row (`operations.ts:244-250`). `ready` ≡ `verified` on MX (`operations.ts:205-208` already folds `signed` into `verified`). Replace with `sending_state ∈ {pending, verified, lost, failed}` and `receiving_state ∈ {off, pending, active, lost}` + `receiving_host`, derive `readiness` JSON in `readiness()` on read, and drop `mailbox_domains` on MX entirely (routing can join `domain_claims` directly; `mailbox-ingest.ts:52-57` already does). Would have prevented the "receiving verified while SES bounced" (receiving was a derived flag with no delivery evidence) and "readiness NULL wedge" (NULL is not a state).

3. **Remove the onboarding gate for Hosted.** `createConnection(kind:'shared')` is already instant-`ready` (`provider-connections.ts:194-200`), yet `/v1/me.connection.status` gates the whole dashboard (`app/src/data/onboarding.ts:29-34`) and members get a dead-end `setup-required` screen until an admin clicks. Create the shared connection inside `onboardNewUser` (`workspaces.ts:41-50`, same CTE), make BYO an opt-in in Settings, and delete the localStorage step machine (`onboarding.ts:7-22`), which is per-browser state that desyncs across devices.

4. **Default `region` on `POST /v1/domains`; let disconnect cascade.** `operations.ts:406` requires `region` though a Hosted workspace has exactly one (`provider_connections UNIQUE(workspace_id)`). `DELETE /v1/connection` 409s while any claim exists (`provider-connections.ts:240-246`), so switching Hosted→BYO means deleting every domain first and re-proving DNS. `reserve_domain_claim` (migration 046) already handles `connection_id IS NULL` claims ("pre-upgrade disconnect"); let delete `SET connection_id=NULL` instead of refusing.

5. **Per-key pending cap of 2,000 is a 429 users will hit.** `sending.ts:26,64-69`. A 5k burst from one key while the shared pool is at 14 msg/s is normal transactional traffic. Risk mitigated: DB bloat. Keep one workspace cap, size it from the account's `max_24_hour_send` (already synced into `provider_account_limits`), drop `keyPending`.

6. **Make tenant provisioning explicit, not a dispatcher side effect.** `tenant_provisioned=false` + `lease_until` (`provider-connections.ts:139-155`) means the first send runs `ensureTenant` from inside `leaseDue` (`dispatcher.ts:224-231`); on failure the mail is silently deferred (`log('warn')` only) and the user sees `queued` forever. Provision the tenant in `createConnection` (one idempotent `CreateTenant`; fall back to the job only on AWS error) and expose `tenant: 'pending'|'ready'|'failed'` in `ConnectionSummary`. This is the "leases stranding onboarding" bug.

7. **Stop giving up on DNS after 72h.** `operations.ts:284-286,339-340`: after the deadline the verifier writes `verificationStatus=FAILED` and stops. A user who adds records on day 4 has to know to click Verify. Keep polling hourly forever; `FAILED` should only mean `DOMAIN_UNAVAILABLE`.

8. **Allow address creation before receiving is active.** `mailbox.ts:361-362` 409s `MAILBOX_DOMAIN_NOT_ENABLED` until MX is observed. Nothing is unsafe about an address on a domain the workspace owns (sending-verified); mail simply won't arrive until MX is up. Same for `deleteDomain`'s 60-second `DOMAIN_BUSY` (`operations.ts:485`) — replace with the claim row lock it already takes.

9. **Attachment and header validation rejects normal input.** `sending.ts:112-128`: 13 extensions, charset params only for text/csv, `ATTACHMENT_CONTENT_TYPE_MISMATCH` for `image/jpg`, magic-byte check, `attachment` disposition may not carry `contentId`. `sending.ts:816-818` rejects non-canonical base64 (e.g. with newlines, which every SDK emits). `mailbox.ts:463` allows only `X-` headers, so `List-Unsubscribe`, `Precedence`, `Auto-Submitted` (which the same API sets itself!) are 422. Keep: size caps, SES's banned-extension list, CRLF header injection check (`sending.ts:433,710`). Remove the rest.

10. **One campaign lifecycle instead of four.** `sending_campaigns.status` + `review_id` + `preparing_review_id`, `campaign_reviews.status`, `campaign_expansions.status` + `paused_at` + `waiting_reason` + `job_id`, and the optional `reviewId` send path (`sending.ts:1114-1169`). Make `expansion` columns of the campaign row, drop the `reviewId` path (Carbon #42), and remove `preparing_review_id` by keying prepare jobs on `(campaign_id, revision)`.
