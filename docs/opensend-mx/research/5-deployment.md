**Deploy OpenSend MX as a new installation, not a second hostname on the production Worker.** Use one HTTPS origin, `https://opensend.mx`, a new Worker named `opensend-mx-api`, an empty database, and a dedicated AWS account. **One code change blocks deployment:** the Worker recognizes the feedback queue by its production name. Renaming only the binding target would silently lose MX delivery events. This was a read-only review; nothing was provisioned or changed.

### Setup order

1. **Prepare and guard CI.** Add `api/wrangler.mx.jsonc` and a separate MX workflow: push branch `opensend-mx`, job guard `github.ref == 'refs/heads/opensend-mx'`, environment `opensend-mx`, concurrency `deploy-opensend-mx`. Mirror the existing installs/checks/build; from `api/` deploy **only** with `npx wrangler deploy --config wrangler.mx.jsonc`. Guard both production deploy and SDK publish jobs with `github.ref == 'refs/heads/main'`: both currently allow manual dispatch as well as main pushes. Never publish the SDK from MX. Restrict each GitHub environment to its branch; move any repository-wide production token into `production`. (`.github/workflows/deploy.yml:3–41`; `.github/workflows/publish-sdk.yml:3–18,31–48`)
2. **[Approval: infrastructure/cost] Provision MX resources.** Confirm which Cloudflare account owns the active `opensend.mx` zone; nameserver delegation alone does not identify it. Prefer an account where the MX token cannot edit production Workers. Create the two queues, R2 bucket, and independent **PlanetScale Postgres** database; production config identifies PlanetScale in AWS `us-east-2`. Create a read/write runtime role and separate schema owner. Point new Hyperdrive at MX with caching disabled and `verify-full` using the appropriate uploaded CA. (`api/wrangler.jsonc:41–46`; `api/README.md:140–152`)
3. **[Approval: credentials and database migration]** Create an MX Google web client: origin `https://opensend.mx`, redirect `https://opensend.mx/api/auth/callback/google`. Generate a fresh `BETTER_AUTH_SECRET` (32+ characters); set MX operator allowlists. With the **direct MX schema-owner** `DATABASE_URL`, verified TLS, MX root, `PUBLIC_URL`, and chosen `DEFAULT_SES_REGION`, run `npm ci` then `npm run migrate` in `api/`; grant runtime access to resulting tables/sequences. Do not migrate through deploy CI. (`api/README.md:72–75,150–166,192`; `api/src/migrate.ts:11–43`)
4. **[Approval: deployment/custom-domain DNS/cost]** Install secrets only on `opensend-mx-api`; deploy the reviewed MX config with `ENABLE_LIVE_SES=false`. 5. **[Separate approval: AWS/DNS/live mail]** Connect the dedicated IAM principal, run regional discovery, then `POST /v1/regions/{region}/provision` with `{"confirm":true}`. Confirm the SNS subscription points to `https://opensend.mx/v1/events/ses`; publish SES-returned DKIM, enable receiving for each verified domain in a supported region, and publish its MX. Check SES production access and quota before enabling live sending. Verify with an explicitly approved recipient, authentic feedback, and inbound receipt. (`api/README.md:190–209,231`; `mcp/README.md:59–64`; `AGENTS.md:36`)
